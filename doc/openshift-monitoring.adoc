= Application Monitoring on Red Hat OpenShift Container Platform (RHOCP) with Prometheus and Grafana

The following guide has been tested and is supported with Red Hat OpenShift Container Platform (RHOCP) versions 4.22, 4.21, 4.20, 4.19, and 4.18.

== Prerequisites

Prior to installing application monitoring on RHOCP, ensure that there is a running application that has a service endpoint for outputting metrics in Prometheus format.

This guide assumes a running application has been deployed to the RHOCP cluster inside a project/namespace called `myapp`, and that its Prometheus metrics endpoint is exposed on path `/metrics`.

== Application Monitoring on RHOCP 4.18+

In RHOCP 4.18+, application monitoring can be set up by enabling monitoring for user-defined projects without the need to install an additional monitoring solution. This solution will deploy a second Prometheus Operator instance inside the `openshift-user-workload-monitoring` namespace that is configured to monitor all namespaces excluding the `openshift-` prefixed namespaces already monitored by the cluster's default platform monitoring. Information regarding the monitoring stack for RHOCP can be found in link:https://docs.redhat.com/en/documentation/monitoring_stack_for_red_hat_openshift/4.22[this document].

There is no separate Grafana deployment that comes with enabling user-defined monitoring, and the existing Grafana instance provided with the default monitoring stack is read-only. Therefore, a community Grafana Operator must be installed to create custom dashboards for viewing your metrics.

. To configure the monitoring stack, refer to the OpenShift guide link:https://docs.redhat.com/en/documentation/monitoring_stack_for_red_hat_openshift/4.22/html/configuring_user_workload_monitoring/index[Configure user workload monitoring].

. Follow the guide link:https://docs.redhat.com/en/documentation/monitoring_stack_for_red_hat_openshift/4.22/html/configuring_user_workload_monitoring/preparing-to-configure-the-monitoring-stack-uwm#enabling-monitoring-for-user-defined-projects_preparing-to-configure-the-monitoring-stack-uwm[1.2.1 Enable monitoring for user-defined projects] to create or edit the config map that allows user-defined projects to be monitored. After creating and configuring the `user-workload-monitoring-config` config map, return to this guide to continue.

. Deploy a Service Monitor inside the `myapp` namespace to define the service endpoint that will be monitored by the Prometheus instance. Add the following YAML to your OpenLibertyApplication Custom Resource (CR):
+
[source,yaml]
----
kind: OpenLibertyApplication
spec:
  ...
  monitoring:
    endpoints:
      - interval: 30s
----

. Under `Observe > Metrics` (formerly `Monitoring > Metrics`), confirm that your service is being monitored by entering queries specific to your application's metrics.

== Deploying an additional Grafana instance for custom dashboards

The following instructions are based on the guide link:++https://www.redhat.com/en/blog/custom-grafana-dashboards-red-hat-openshift-container-platform-4++[Custom Grafana dashboards for Red Hat OpenShift Container Platform 4]. This Grafana instance will be connected to OpenShift monitoring in the `openshift-monitoring` namespace. Additional Grafana dashboards will increase the load on the Prometheus service, so pay attention to Prometheus CPU and memory usage when deploying dashboards.

. Create a new namespace (e.g. `my-grafana`).

. From `Ecosystem > Software Catalog`, install the Grafana Operator into the `my-grafana` namespace.

. From Installed Operators, select the Grafana Operator. For the Grafana resource, click *Create Instance* to create a new Grafana instance (default name is `grafana-a`). Take note of the username and password for login (by default, it is `start` and `root`).

. Upon creating the new Grafana instance, the service account `grafana-a-sa` will be created. Give it the `cluster-monitoring-view` role using `oc adm policy add-cluster-role-to-user cluster-monitoring-view -z grafana-a-sa` and obtain a service account token secret using `oc create token grafana-a-sa --duration=8760h -n my-grafana`.
+
NOTE: Example Grafana instance YAML files can be found link:++https://grafana.github.io/grafana-operator/docs/examples/grafana/++[here]. The Grafana Operator's `apiVersion` and Custom Resources have been renamed since the creation of the Red Hat blog post. When deploying the Grafana Datasource in the blog, use the YAML provided below instead.

. Next, create a Grafana Data Source using the YAML below. Substitute `${BEARER_TOKEN}` with the token created in the previous step:
+
[source,yaml]
----
kind: GrafanaDatasource
apiVersion: grafana.integreatly.org/v1beta1
metadata:
  name: prometheus-grafanadatasource
  namespace: my-grafana
spec:
  datasource:
    access: proxy
    editable: true
    isDefault: true
    jsonData:
      httpHeaderName1: 'Authorization'
      timeInterval: 5s
      tlsSkipVerify: true
    name: Prometheus
    secureJsonData:
      httpHeaderValue1: 'Bearer ${BEARER_TOKEN}'
    type: prometheus
    url: 'https://thanos-querier.openshift-monitoring.svc.cluster.local:9091'
  instanceSelector:
    matchLabels:
      dashboards: grafana-a
  plugins:
    - name: grafana-clock-panel
      version: 1.3.0
----

. Deploy the dashboard template by creating a Grafana Dashboard instance from link:++https://github.com/OpenLiberty/open-liberty-operator/blob/main/doc/guides-code/grafana_dashboard.yaml.txt++[grafana_dashboard.yaml.txt] to view all services currently being monitored. Ensure that the namespace in this YAML matches your target namespace.

. Under `Networking > Routes`, open the Grafana route URL to view the dashboard. You can now observe all application metrics gathered by Prometheus.

== Installation Complete

You now have the Prometheus and Grafana stack installed and configured to monitor your applications. Import custom dashboards and visit the Grafana route to visualize your metrics.
